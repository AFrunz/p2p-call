# Развёртывание своего сервера

Сервер нужен **только тем, кому не хватило прямого соединения**. Приложение по
умолчанию работает без него: участники обмениваются кодами вручную, медиа идёт
напрямую. Свой сервер решает два случая — symmetric NAT и сети, где UDP зарезан
целиком, — и заодно избавляет от ручного обмена кодами: подключение становится
по ссылке.

## Что в него входит

| Компонент | Роль |
|---|---|
| **caddy** | TLS от Let's Encrypt и обратный прокси. Без HTTPS браузер не даст странице с `github.io` открыть websocket |
| **signaling** | Ретранслирует запечатанные блобы между двумя участниками и выдаёт временные учётные данные TURN |
| **coturn** | Ретранслятор медиа для тех, кто не пробился напрямую |

## Что нужно заранее

- Машина с публичным IP и Linux (`network_mode: host` у coturn на macOS/Windows не работает).
- Если машина облачная и видит только приватный адрес (GCP, AWS, Yandex Cloud), понадобится пара адресов для `TURN_EXTERNAL_IP` — иначе TURN раздаст собеседникам внутренний адрес. Посмотреть свой приватный: `ip -4 addr show scope global | grep inet`.
- Домен, у которого A- или AAAA-запись указывает на эту машину. Если домена нет, подойдёт `<ваш-ip>.sslip.io` — эта служба резолвит адрес прямо из имени, и Let's Encrypt выдаёт на него сертификат.
- Открытые порты: `80/tcp`, `443/tcp`, `3478/tcp+udp`, `49160-49200/udp`.
- Docker с плагином compose.

## Развёртывание

```bash
git clone <репозиторий> && cd p2p-call
cp .env.example .env

# заполните DOMAIN, ACME_EMAIL, TURN_EXTERNAL_IP и сгенерируйте секрет:
openssl rand -hex 32

docker compose up -d
```

Проверка:

```bash
curl https://<ваш-домен>/health
# {"status":"ok","rooms":0}
```

В приложении откройте настройки и укажите адрес сигналинга:
`wss://<ваш-домен>/ws`. После этого вместо кода появится кнопка «Создать ссылку».

## Почему сервер не может подслушать звонок

Ссылка-приглашение выглядит так:

```
https://user.github.io/p2p-call/#j=<приглашение>
```

Всё содержательное лежит **после `#`**. Фрагмент URL по устройству HTTP не
отправляется на сервер — ни в запросе, ни в заголовке `Referer`. Внутри
приглашения секрет комнаты на 32 байта, и он остаётся исключительно в браузерах
участников.

Дальше этот секрет работает в двух местах:

1. **Шифрует сам сигналинг.** Клиент запечатывает SDP в AES-256-GCM на ключе,
   выведенном из секрета комнаты. Сервер видит идентификатор комнаты и
   непрозрачный блоб — ни SDP, ни DTLS-fingerprint ему недоступны. Классическая
   атака «сервер подменяет fingerprint и садится в середину» здесь не работает.
2. **Подмешивается в ключи медиа.** Даже если бы сигналинг был открытым,
   сквозной слой шифрования кадров держится на секрете, которого у сервера нет.

Что сервер всё-таки видит: IP-адреса участников, время звонка, идентификатор
комнаты, а при ретрансляции через TURN — объём и тайминги трафика. Содержимое —
нет.

## Настройки

Обязательные три значения — в `.env`, остальное имеет разумные умолчания:

| Переменная | Умолчание | Смысл |
|---|---|---|
| `DOMAIN` | — | Домен сервера, он же realm для TURN |
| `ACME_EMAIL` | — | Почта для Let's Encrypt |
| `TURN_SECRET` | — | Общий секрет сигналинга и coturn, `openssl rand -hex 32` |
| `TURN_PORT` | `3478` | Порт TURN |
| `TURN_MIN_PORT` / `TURN_MAX_PORT` | `49160` / `49200` | Диапазон для медиа: ~40 портов ≈ 20 одновременных ретранслируемых звонков |
| `TURN_CREDENTIAL_TTL` | `3600` | Сколько живут выданные учётные данные |
| `MAX_ROOMS` | `500` | Потолок одновременных комнат |
| `ROOM_TTL_SECONDS` | `600` | Сколько ждать возвращения в опустевшую комнату |

Сервер падает на старте с внятным сообщением, если конфигурация противоречива —
например, задан `TURN_HOST` без секрета. Это намеренно: полурабочий TURN
обнаружился бы только в момент несостоявшегося звонка.

## Про турн и `turns:`

По умолчанию поднимается обычный `turn:` на 3478 (UDP и TCP). Это не дыра:
учётные данные — временные HMAC-токены, которые приезжают по уже защищённому
websocket, а медиа внутри и так зашифровано дважды (DTLS-SRTP и наш слой).

`turns:` на 5349 имеет смысл в сетях, выпускающих только TLS. Он требует
сертификата: проще всего дать coturn читать тот, что уже получил Caddy, и
выставить `TURN_TLS=true` у сигналинга. Из коробки не включено, чтобы
развёртывание оставалось одной командой.

## Сколько это стоит по трафику

TURN ретранслирует весь поток: звонок 720p — примерно 2 Мбит/с в каждую сторону,
то есть около 1.8 ГБ на час разговора в обе стороны. Прямые соединения через
сервер не идут вообще, а их большинство: TURN включается только когда ICE не
нашёл прямого пути.

## Раздача фронтенда с этого же сервера

По умолчанию страница живёт на GitHub Pages, а сервер занимается только
сигналингом. Если хочется всё на одной машине — соберите фронтенд
(`npm run build`), примонтируйте `./dist` в `/srv` контейнера caddy и
раскомментируйте соответствующий блок в `deploy/Caddyfile`.

## Обновление и остановка

```bash
docker compose pull && docker compose up -d --build   # обновить
docker compose logs -f signaling                      # смотреть логи
docker compose down                                   # остановить
```
