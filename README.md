# p2p-call

Видеозвонки между двумя участниками напрямую, со сквозным шифрованием. Страница —
статика на GitHub Pages, сервера по умолчанию нет вовсе.

- **Техническое задание** — [TZ.md](TZ.md)
- **Свой сервер** (нужен не всем) — [DEPLOY.md](DEPLOY.md)

## Как это работает

Приложение работает в двух режимах.

**Без сервера (по умолчанию).** Участники обмениваются кодами подключения вручную —
копипастом или через QR. Соединение устанавливается напрямую, посредников нет.
Работает в большинстве сетей.

**Со своим сервером.** Нужен, когда прямое соединение не устанавливается: symmetric
NAT у мобильных операторов, корпоративные сети с зарезанным UDP. В этом режиме
подключение идёт по ссылке, без обмена кодами. Секрет комнаты лежит во фрагменте
ссылки, после `#`, и на сервер не попадает — поэтому сервер видит только
непрозрачные блобы и не может влезть в середину.

Прежде чем предлагать сервер, приложение честно пытается обойтись без него:
IPv6, локальная сеть, hole punching через несколько STUN, автоматический ICE
restart. Тип NAT определяется заранее — предупреждение приходит до того, как вы
впустую перешлёте код.

## Шифрование

Два слоя, оба всегда включены:

1. **DTLS-SRTP** — встроен в WebRTC, отключить нельзя. Ключи через ECDHE P-256.
   Поскольку в режиме без сервера отпечаток сертификата едет из рук в руки, а не
   через посредника, этот слой сам по себе даёт настоящий E2EE.
2. **Шифрование кадров** — AES-256-GCM в отдельном воркере, поверх транспортного.
   Ключи выводятся через ECDH + HKDF, ротация каждые 30 секунд.

Дополнительно: необязательная **общая парольная фраза** (защищает, даже если канал
обмена кодами скомпрометирован) и **контрольная фраза SAS** из пяти слов для
сверки голосом.

Настроек «уровня шифрования» нет намеренно: AES-GCM идёт через аппаратный AES-NI
и стоит доли процента CPU, поэтому выбирать между качеством и безопасностью не
из чего.

## Разработка

```bash
npm install
npm run dev        # локальный сервер разработки
npm test           # 291 тест
npm run typecheck
npm run build      # сборка в dist/
```

Логика вынесена в чистые модули без обращений к DOM — именно они покрыты тестами.
Браузерная часть (`RTCPeerConnection`, воркер, `getUserMedia`) намеренно тонкая.

```
src/
  signaling/   коды подключения, разбор SDP, ссылки-приглашения, клиент сигналинга
  crypto/      ECDH и HKDF, раскладка кадров, SAS, воркер шифрования
  net/         диагностика NAT, конфигурация ICE
  call/        оркестратор звонка, медиа, статистика, encoded transform
  protocol/    контрольный канал и протокол сигналинга (общий с сервером)
  ui/          форматирование для интерфейса
server/        сигнальный сервер, разворачивается через Docker
```

## Подключение без камеры и микрофона

Войти в звонок можно и без своих устройств — участник будет смотреть и слушать.
Если доступна только часть, работает и она: звонок с одним микрофоном на машине
без камеры устанавливается штатно.

## Ограничения

- Ровно два участника: ручной сигналинг большего не позволяет.
- Без своего сервера примерно 10–20% соединений не установятся — это свойство
  NAT, а не приложения.
- Сквозное шифрование кадров требует поддержки Encoded Transform. Если её нет,
  звонок работает на транспортном шифровании, о чём в интерфейсе висит
  предупреждение.
